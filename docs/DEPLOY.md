# Развёртывание

## Вариант 1. Бесплатно: Render + Neon (рекомендуется для старта)

| Сервис                       | Что даёт                          | Ограничение бесплатного тарифа                             |
| ---------------------------- | --------------------------------- | ---------------------------------------------------------- |
| [Neon](https://neon.tech)    | PostgreSQL                        | 0,5 ГБ: хватит на тысячи учеников и лет результатов        |
| [Render](https://render.com) | запуск приложения по `Dockerfile` | «засыпает» после 15 минут без запросов (решается в шаге 3) |

> Бесплатный Render «засыпает», если на сайт 15 минут никто не заходит. Как сделать, чтобы сайт работал круглосуточно, описано в [шаге 3](#шаг-3-сайт-доступен-круглосуточно).

### Шаг 1. База данных в Neon

1. Зарегистрируйтесь на neon.tech и создайте проект (регион: Frankfurt, ближе всего к Украине).
2. Скопируйте **Connection string**. Она выглядит как `postgresql://user:pass@ep-xxx.eu-central-1.aws.neon.tech/neondb?sslmode=require`.

### Шаг 2. Приложение в Render

1. Зарегистрируйтесь на render.com через GitHub.
2. **New → Blueprint** → выберите этот репозиторий. Render прочитает `render.yaml`.
3. В поле `DATABASE_URL` вставьте строку из Neon. `JWT_SECRET` сгенерируется автоматически.
4. Нажмите **Apply**. Через несколько минут сайт будет доступен по адресу вида `https://infoklas.onrender.com`.
5. Откройте сайт → «Я вчитель» → зарегистрируйтесь. Первый учитель регистрируется свободно, после этого регистрация закрывается.

Каждый push в основную ветку автоматически обновляет сайт. Миграции базы применяются сами при запуске.

### Шаг 3. Сайт доступен круглосуточно

Выберите один из двух способов.

#### Способ А. Бесплатно: мониторинг, который не даёт сайту уснуть

Внешний сервис каждые 5 минут заходит на сайт. Render видит посещения и не усыпляет сервер, а вы получаете письмо, если сайт перестал отвечать.

1. Зарегистрируйтесь на [uptimerobot.com](https://uptimerobot.com) (бесплатный тариф).
2. **+ New monitor**:
   - **Monitor type:** HTTP(s)
   - **URL:** `https://ваш-сайт.onrender.com/api/health`
   - **Monitoring interval:** 5 minutes
   - **Alert contacts:** ваша почта
3. Сохраните. Через несколько минут монитор станет зелёным (**Up**).

Для надёжности можно добавить второй, независимый «будильник»: на [cron-job.org](https://cron-job.org) создайте задание (Create cronjob) с тем же адресом и расписанием «Every 5 minutes».

Почему это бесплатно:

- Render даёт 750 бесплатных часов работы в месяц. Одному сайту, работающему круглосуточно, нужно не больше 744 часов.
- Адрес `/api/health` специально не обращается к базе данных. Проверки держат «проснувшимся» только сервер, а база Neon спит, пока ею никто не пользуется, и не тратит свой бесплатный лимит. Когда учитель или ученик заходит на сайт, база просыпается меньше чем за секунду.

Ограничение: у бесплатного тарифа нет гарантий. Render иногда перезапускает сервисы на обслуживание, и сайт может быть недоступен около минуты. Если это станет критично, используйте способ Б.

#### Способ Б. Гарантированно: платный тариф Render (около $7 в месяц)

В Render: сервис **infoklas → Settings → Instance Type → Starter**. Сервер больше не засыпает, и Render обновляет сайт без простоя. Код и база остаются прежними. Мониторинг из способа А всё равно полезно оставить: он сообщит о проблемах.

### Резервные копии базы

Neon хранит историю изменений и позволяет восстановить базу на прошлый момент (Restore в панели проекта; глубина истории зависит от тарифа). Для собственной копии раз в месяц или в конце четверти выполните на компьютере с установленным PostgreSQL:

```bash
pg_dump "строка-подключения-из-Neon" > infoklas-backup-$(date +%F).sql
```

### Свой домен (по желанию)

В Render: Settings → Custom Domains. HTTPS настраивается автоматически.

## Вариант 2. Свой сервер с Docker

Сервер работает круглосуточно и не засыпает. Контейнеры перезапускаются автоматически после сбоя или перезагрузки машины (`restart: unless-stopped`). Подойдёт любой VPS (например, бесплатная виртуальная машина Oracle Cloud Always Free или VPS примерно за 5 €/мес).

```bash
git clone <репозиторий> && cd TaskSchoolsInfo
cat > .env <<EOF
JWT_SECRET=$(node -e "console.log(require('crypto').randomBytes(48).toString('base64url'))")
POSTGRES_PASSWORD=придумайте-надёжный-пароль
TRUST_PROXY=true
EOF
docker compose up -d --build
```

Приложение слушает порт 3000. Для HTTPS поставьте перед ним [Caddy](https://caddyserver.com), он сам получает сертификат:

```
# /etc/caddy/Caddyfile
infoklas.example.com {
    reverse_proxy localhost:3000
}
```

Резервная копия базы:

```bash
docker compose exec db pg_dump -U infoklas infoklas > backup-$(date +%F).sql
```

## Переменные окружения

| Переменная       | Обязательна | Описание                                                            |
| ---------------- | ----------- | ------------------------------------------------------------------- |
| `DATABASE_URL`   | да          | строка подключения к PostgreSQL                                     |
| `JWT_SECRET`     | да          | случайная строка ≥ 32 символов для подписи входа                    |
| `TEACHER_SIGNUP` | нет         | `true`, чтобы после первого учителя могли регистрироваться и другие |
| `TRUST_PROXY`    | нет         | `true` за прокси (Render, Caddy, nginx)                             |
| `PORT`           | нет         | порт, по умолчанию 3000                                             |
| `WEB_DIST_DIR`   | нет         | папка собранного интерфейса (в Docker уже задана)                   |
| `LOG_LEVEL`      | нет         | подробность логов: `info` (по умолчанию), `warn`, `debug`           |

## Важно знать

- Сервер устойчив к перебоям базы данных. При старте он до минуты ждёт, пока база станет доступна. Если облачная база оборвёт соединение, сервер переподключится сам и продолжит работать.
- При обновлении (push в `main`) сервер останавливается корректно: незавершённые живые игры сохраняют результаты в журнал.

- Состояние **живой игры** хранится в памяти сервера. Если сервер перезапустится посреди игры, результаты уже сыгранных вопросов сохранятся в журнал, а игру нужно будет начать заново. Домашние задания это не затрагивает.
- Приложение рассчитано на один экземпляр сервера. Для школы или нескольких школ этого с запасом хватит.
