# Перенос: код, данные, переключение сайта

Главный принцип: **Клас-пульт и действующий ІнфоКлас продолжают работать до дня переключения**. Поэтому новая платформа собирается в отдельной папке `apps/platform`: Render продолжает публиковать `apps/web` + `apps/server` из `main`, и слияние этапов в `main` их не ломает. Всё новое разрабатывается и проверяется на эмуляторе Firebase. Боевые данные при переносе **копируются**, а не перемещаются, поэтому откат остаётся возможен.

## 1. Откуда берётся код

Целевая структура репозитория `TaskSchoolsInfo`:

```
packages/shared/        общий код (есть): вопросы, проверка ответов, + импорт, ПК, ссылки, склонения
apps/platform/          НОВОЕ: интерфейс единой платформы (кабинет, ученик, проектор, пульт урока)
apps/web/, apps/server/ действующий ІнфоКлас на Render, НЕ меняется до переключения; удаляется на этапе 8
firestore/              НОВОЕ: firestore.rules, firestore.indexes.json, тесты правил
e2e/                    НОВОЕ: сценарии Playwright в Chromium 109 (ученик и учитель в разных контекстах)
tools/                  НОВОЕ: эмуляторы, загрузка Chromium 109, скрипты миграции
firebase.json, .firebaserc   НОВОЕ: из Клас-пульта (hosting → apps/platform/dist)
```

## 2. Перенос данных

Перенос выполняет скрипт `tools/migrate/*.ts` на ноутбуке учителя или в GitHub Actions с секретом. Он работает через **Firebase Admin SDK** (ключ сервисного аккаунта из консоли Firebase, который нигде не сохраняется) и **только добавляет** новые документы.

Порядок: **сухой прогон** (`--dry-run`, выводит, что будет создано) → резервная копия → перенос → сверка количества.

### Из Клас-пульта (Firestore того же проекта)

| Было                                                     | Станет                                                     | Примечание                                                                                                                                                                                               |
| -------------------------------------------------------- | ---------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `tests/{id}` + `keys/{id}`                               | `quizzes/{id}`                                             | вопрос `{text, options[]}` + индекс ответа → `{id: "q1", type: "single", prompt, options: [{id: "a", text}…], correctOptionId}`; `folder` сохраняется                                                    |
| `sessions/{resetAt_testId}`                              | `assignments/{то же id}`, `kind: "lesson"`, `legacy: true` | класс определяется по `classLabel`: для каждого уникального названия создаётся класс (год обучения берётся из цифры в названии, например `5-А` → 5, иначе спросить). Снимок вопросов и ключа — из сессии |
| `results/{id}` с `sessionId`                             | `guestResults/{id}`                                        | учеников тогда не было в списках, поэтому результаты остаются «по ПК и имени». Они видны в Истории, но не в журнале                                                                                      |
| `results` без `sessionId` (до 25.09.2026)                | не переносятся                                             | в Клас-пульте они тоже не попадают в историю                                                                                                                                                             |
| `secret/teacher`, `setup/state`, `teachers/*`, `clock/*` | **остаются на месте**                                      | те же коллекции и правила: код учителя не меняется, повторно входить не нужно                                                                                                                            |
| `control/state`, `students/*`, `reveals/*`               | не переносятся                                             | временное состояние урока                                                                                                                                                                                |

### Из ІнфоКласа (PostgreSQL на Neon)

| Было (таблица)                                | Станет                                                                                                                                             |
| --------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------- |
| `classes`                                     | `classes/{id}` + `joinCodes/{joinCode}`                                                                                                            |
| `students`                                    | `classes/{classId}/roster/{id}` + `studentSecrets/{id}`. Действующие пароли из 3 картинок **продолжают работать**. Новые выдаются из 4 картинок    |
| `quizzes`                                     | `quizzes/{id}` (формат вопросов тот же)                                                                                                            |
| `assignments`                                 | `assignments/{id}` (`kind: "homework"`, ответы вынесены в `assignmentKeys/{id}`; `show_correct=true` → `reveal: "immediate"`, `false` → `"never"`) |
| `submissions`                                 | `submissions/{assignmentId}_{studentId}_{attempt}`                                                                                                 |
| `live_sessions` (`finished`) + `live_results` | `games/{id}` (`status: "finished"`) + `gameResults/{id}_{studentId}`                                                                               |
| `teachers`                                    | не переносится: вход по коду учителя                                                                                                               |

Идентификаторы (UUID) сохраняются, поэтому ссылки и сводки остаются согласованными. Если в ІнфоКласе ещё нет реальных данных (только проверочные), этот перенос пропускается.

### Резервная копия

На тарифе Spark нет встроенного экспорта Firestore (`gcloud firestore export` требует Blaze). Поэтому перед переносом скрипт `tools/migrate/backup.ts` сохраняет **все коллекции в JSON-файлы** на ноутбук учителя. Для ІнфоКласа используется `pg_dump` (см. `docs/DEPLOY.md`).

## 3. Правила во время разработки

У проекта Firebase **один набор правил** на всю базу. Пока Клас-пульт работает на уроках, новые правила **обязаны включать старые без изменений**: `control`, `students`, `tests`, `keys`, `sessions`, `reveals`, `results`. Новые коллекции названы иначе, поэтому не пересекаются со старыми.

- Первая публикация новых правил (этап 2) = старые правила + новые блоки. Тест правил прогоняет **оба** набора: 19 групп тестов Клас-пульта и новые.
- Интерфейс новой платформы до переключения публикуется в **превью-канал** Firebase Hosting (`firebase hosting:channel:deploy preview`), а не на основной адрес. Превью-канал бесплатный и получает свой временный адрес.
- Старые блоки удаляются из правил только через 2 недели после переключения (этап 8).

## 4. Переключение (день X)

Лучше всего в выходной. Это займёт около часа.

1. Проверить, что у всех этапов выполнены критерии готовности ([ROADMAP.md](ROADMAP.md)) и CI зелёный.
2. Поставить на git-метку текущий Клас-пульт: `v1-final` в репозитории `klas-pult`.
3. Резервная копия: `tools/migrate/backup.ts` (Firestore в JSON) и `pg_dump` ІнфоКласа.
4. Перенос: `migrate --dry-run` → проверить отчёт → `migrate` → сверка количества документов.
5. Опубликовать новую платформу на основной адрес: `firebase deploy --only hosting,firestore`.
   - `https://klas-pult.web.app` — страница ученика (как раньше, школьные ПК ничего не замечают);
   - `https://klas-pult.web.app/admin.html` — переадресация на кабинет учителя (для закладок);
   - `https://klas-pult.web.app/t` — кабинет, `/join/<код>` — вход по ссылке из Classroom.
6. Проверка учителем по чек-листу: вход по коду, классы на месте, тест из банка отправляется на ПК, домашнее задание открывается с телефона, журнал показывает перенесённые результаты.
7. Если что-то не так → **откат** (ниже).

### Откат

Старые коллекции при переносе не менялись, поэтому откат занимает около 5 минут:

```bash
cd klas-pult && git checkout v1-final && firebase deploy --only hosting,firestore:rules
```

Всё, что учитель успел сделать в новой платформе между переключением и откатом, остаётся в новых коллекциях. Когда проблему исправят, повторное переключение подхватит эти данные.
