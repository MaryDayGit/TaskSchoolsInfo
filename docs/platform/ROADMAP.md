# Этапы объединения

Работа идёт по этапам. Каждый этап — отдельный PR (или несколько) с зелёным CI и проверкой учителем. Клас-пульт работает на уроках до этапа 7.

| Этап | Что                                         | Для учителя видно                      | Оценка     |
| ---- | ------------------------------------------- | -------------------------------------- | ---------- |
| 0    | Утверждение решений                         | —                                      | 1 разговор |
| 1    | Фундамент: Firebase, старые браузеры, тесты | превью-адрес с пустым кабинетом        | 1–2 сессии |
| 2    | Классы, ученики, вход                       | классы и вход учеников на превью       | 1–2 сессии |
| 3    | Банк тестов и домашние задания              | задания и журнал на превью             | 2 сессии   |
| 4    | Пульт урока                                 | всё из Клас-пульта на превью           | 2–3 сессии |
| 5    | Живая игра на Firestore                     | игра на превью                         | 1 сессия   |
| 6    | История, журнал, миграция данных            | перенесённые данные на превью (копия)  | 1–2 сессии |
| 7    | Переключение                                | новая платформа на `klas-pult.web.app` | 1 выходной |
| 8    | Уборка                                      | —                                      | 1 сессия   |

## Этап 0. Утверждение решений

Учитель подтверждает или меняет пункты раздела [«Решения на утверждение»](README.md#решения-на-утверждение). Изменения вносятся в эти документы до начала этапа 1.

## Этап 1. Фундамент

- `firebase.json`, `.firebaserc` (проект `klas-pult`), эмуляторы (Auth, Firestore, Hosting), `tools/` для запуска.
- новое приложение `apps/platform` (действующие `apps/web` и `apps/server` не трогаются): Firebase SDK, хуки `useAuth` (анонимный вход только при отсутствии пользователя), `useDoc`/`useQuery` с переподключением, сверка часов.
- Сборка под `chrome109` / `firefox115`; `browserslist`; ESLint `compat`; stylelint; запрет `window.confirm/prompt/alert`; бюджет размера.
- Загрузка Chromium 109 в CI и кеширование: снапшот Linux **r1070052** = 109.0.5414.0 (в Клас-пульте на Windows тот же 109.0.5414.0, снапшот r1070054).
- Каркас правил: старые правила Клас-пульта без изменений + `isTeacher`, `clock`. Перенос 19 групп тестов правил Клас-пульта.
- Вход учителя по коду (экраны «Перший запуск» и «Код учителя»).
- SVG-набор иконок и 12 картинок-паролей.
- Превью-канал Hosting и публикация превью из CI.

**Готово, когда:**

- в Chromium 109 открываются страница ученика и кабинет, вход по коду работает (сценарий `e2e/teacher-login.spec.ts`);
- React, роутер и библиотеки работают в Chromium 109 (иначе заменены);
- JS страницы ученика ≤ 200 КБ gzip;
- все тесты правил Клас-пульта проходят на объединённых правилах;
- превью-адрес открывается у учителя.

## Этап 2. Классы, ученики, вход

- Кабинет: классы, ученики (список, вставка столбцом), карточки входа (SVG-картинки, печать), «Новий пароль», «Вийти з усіх пристроїв», сведения о входах.
- Ученик: код класса → имя → 4 картинки / пароль; гостевой вход (номер ПК + имя); номер ПК запоминается.
- Правила: `classes`, `joinCodes`, `roster`, `studentSecrets`, `bindings`, `isStudentOf()`.

**Готово, когда:**

- тесты правил: неверный пароль, чужой `uid`, смена пароля отключает старое устройство, ученик не читает `studentSecrets`;
- сценарий: учитель создаёт класс и учеников → ученик в другом браузерном контексте (Chromium 109, и отдельно мобильный размер экрана) входит по картинкам;
- пароли из 3 картинок (перенесённые) тоже принимаются.

## Этап 3. Банк тестов и домашние задания

- Банк: редактор ІнфоКласа (3 типа вопросов) + папки, поиск, «давали», «Відповіді», импорт из текста (`importer.ts`), шаблоны НУШ.
- Домашние задания: выдача (срок, попытки, режим разбора), ссылка и кнопка Google Classroom, выполнение учеником (по одному вопросу, черновик, озвучка для 2–4), разбор.
- Результаты задания и журнал (сводки `summary`), CSV.
- Правила: `quizzes`, `assignments`, `assignmentKeys`, `submissions`.

**Готово, когда:**

- тесты правил: срок, попытки, повтор попытки, пропуск номера, чужой `studentId`, ключ до сдачи недоступен, `after_due` открывается только после срока;
- сценарий: выдача → сдача с «телефона» → результат у ученика → результаты и журнал у учителя → CSV;
- журнал пересчитывает баллы по «сырым» ответам (модульный тест: подделанный балл не учитывается).

## Этап 4. Пульт урока

- Перенос всего Клас-пульта: «Надіслати учням» (ссылка, сообщение, тест), «Кому», «Зараз на екранах», прогресс, карточки ПК со статусами, блокировка, таймер, руки, «Я закінчив(ла)», разбор, «Правильні відповіді», темы, адаптивность.
- «Новий клас» = выбор класса из списка, ученики входят по списку этого класса; гостевой вход.
- Тест на уроке = задание `kind: "lesson"`, результаты сразу в журнале.
- Правила: `rooms`, `pcs`, `guestResults`.

**Готово, когда** все критерии ТЗ Клас-пульта (§14) проходят на новой платформе в Chromium 109:

- ссылка у ученика за 1–2 с; только ПК 03 → не появляется на ПК 07;
- тест → правильный балл → CSV с кириллицей;
- пульт и страница ученика в одном браузере не выкидывают друг друга;
- после «Новий клас» все снова видят вход, номер ПК подставлен;
- таймер совпадает на ПК со сбитыми на 2 часа часами;
- сценарии `mobile` (375, 360, 768, 900 px) без горизонтальной прокрутки;
- расчёт и **замер** в эмуляторе: урок 30 ПК × 45 мин < 5 000 записей.

## Этап 5. Живая игра на Firestore

- Ведущий в браузере учителя (`host.ts`: чистая функция состояний из `LiveManager`), экран проектора, экран ученика.
- Правила: `games`, `gameKeys`, `answers` (дедлайн, текущий вопрос, один ответ), `gameResults`.

**Готово, когда:**

- модульные тесты `host.ts` повторяют все сценарии прежнего `live.test.ts` (полная игра, авто-показ, досрочное завершение, игра в лобби не попадает в журнал, режим 2–4 без рейтинга и бонуса);
- тесты правил: ответ после дедлайна, повторный ответ, ответ на другой вопрос отклоняются;
- сценарий: учитель и 3 ученика, задержка от ответа до обновления у ведущего ≤ 1,5 с;
- ведущий перезагрузил вкладку → игра продолжается с того же вопроса.

## Этап 6. История, журнал, миграция данных

- Вкладка «Історія» (из Клас-пульта) поверх заданий `kind: "lesson"` и `guestResults`; статистика `stats.ts`.
- Журнал: домашние задания + уроковые тесты + игры.
- Скрипты `tools/migrate/*`: резервная копия, перенос из Клас-пульта и из ІнфоКласа, сухой прогон, сверка.

**Готово, когда:**

- перенос прогнан на **копии** боевых данных в эмуляторе: количество совпадает, баллы в Истории совпадают с Клас-пультом (сравнение по CSV);
- учитель проверил на превью свою историю и тесты.

## Этап 7. Переключение

По чек-листу из [MIGRATION.md](MIGRATION.md#4-переключение-день-x), с готовым планом отката.

**Готово, когда** учитель провёл на новой платформе неделю уроков, домашних заданий и хотя бы одну живую игру без отката.

## Этап 8. Уборка

- Удалить старые коллекции и блоки правил, `apps/web`, `apps/server`, `Dockerfile`, `docker-compose.yml`, `render.yaml`, сервис Render, проект Neon, мониторинг UptimeRobot.
- Переписать документацию `docs/*` под Firebase (развёртывание сводится к `firebase deploy`), руководство учителя дополнить разделом «Пульт уроку».
- Архивировать репозиторий `klas-pult` с указанием нового адреса.

## Тесты

Тесты, которые должны проходить в CI на каждом этапе:

| Набор                                                                                                 | Инструмент                                  | Где                                |
| ----------------------------------------------------------------------------------------------------- | ------------------------------------------- | ---------------------------------- |
| Модульные: вопросы, проверка ответов, импорт, склонения, ссылки, ПК, статистика, ведущий игры, журнал | Vitest                                      | `packages/shared`, `apps/platform` |
| Правила Firestore (старые группы Клас-пульта + новые)                                                 | `@firebase/rules-unit-testing` на эмуляторе | `firestore/`                       |
| Сценарии: учитель и ученик в разных контекстах                                                        | Playwright + **Chromium 109** + эмуляторы   | `e2e/`                             |
| Совместимость: браузерные API и CSS                                                                   | ESLint `compat`, stylelint                  | весь интерфейс                     |
| Бюджет размера страницы ученика                                                                       | скрипт после `vite build`                   | CI                                 |

Правило приёмки: если сценарий не проходит в Chromium 109, изменение не принимается. Если тест правил не проходит, правила не публикуются.

## Открытые вопросы (решить по ходу)

- Нужен ли второй кабинет (`rooms/{roomId}`), например для урока в классе с проектором и телефонами без ПК? Модель данных это позволяет, интерфейс на этапе 4 делается для одного кабинета.
- Автосдача теста по таймеру («тест з обмеженням часу» из идей Клас-пульта): добавить в этап 4 или позже?
- Картинки в вопросах: нужен Firebase Storage. На тарифе Spark он доступен только при привязанной карте (Blaze) для новых проектов. Решить до реализации.
- Интеграция с Google Classroom API (автоматическая выгрузка оценок) требует входа учителя через Google: отдельное решение после этапа 8.
