# Этапы объединения

Работа идёт по этапам. Каждый этап — отдельный PR (или несколько) с зелёным CI и проверкой учителем. Клас-пульт работает на уроках до этапа 7.

| Этап | Что                                         | Для учителя видно                      | Оценка     |
| ---- | ------------------------------------------- | -------------------------------------- | ---------- |
| 0    | Утверждение решений                         | —                                      | 1 разговор |
| 1    | Фундамент: Firebase, старые браузеры, тесты | превью-адрес с пустым кабинетом        | 1–2 сессии |
| 2    | Классы, ученики, вход                       | классы и вход учеников на превью       | 1–2 сессии |
| 3    | Банк тестов и домашние задания              | задания и журнал на превью             | 2 сессии   |
| 4    | Пульт урока                                 | всё из Клас-пульта на превью           | 2–3 сессии |
| 5    | Живая игра на Firestore                     | игра на превью                         | 1 сессия   |
| 6    | История, журнал, миграция данных            | перенесённые данные на превью (копия)  | 1–2 сессии |
| 7    | Переключение                                | новая платформа на `klas-pult.web.app` | 1 выходной |
| 8    | Уборка                                      | —                                      | 1 сессия   |

**Отступления от плана:**

- **Firebase JS SDK 11.10, а не 12.** В Firestore из SDK 12 входит библиотека регулярных выражений `re2js` (+45 КБ gzip), и страница ученика не укладывалась в бюджет. Переход на 12 возможен, когда бюджет позволит. Тесты правил используют SDK 12 (этого требует `@firebase/rules-unit-testing` 5): на приложение это не влияет.
- **React Router в декларативном режиме** (`<BrowserRouter>`, `<Routes>`) вместо режима данных: −17 КБ gzip. В этом режиме нет `useBlocker`, поэтому предупреждение о несохранённом тесте на этапе 3 делается своим способом (`beforeunload` + своё окно при переходе внутри кабинета).
- **Вход Firebase через `initializeAuth`** только с нужным хранением сессии (без модуля всплывающих окон входа через Google): −3 КБ gzip. Если понадобится вход через Google (Classroom API), модуль добавляется.
- **Проверка CSS (stylelint)** перенесена на этап 2, когда появится больше стилей (сделано на этапе 2).
- **ESLint `compat` ловит не всё:** глобальные API (например, `URLPattern`) ловит, а методы объектов (например, `Array.prototype.toSorted` или `document.startViewTransition`) нет. Главная гарантия — сценарии в настоящем Chromium 109.
- **Сверка часов** (`clock/{uid}`) перенесена на этап 4: она нужна таймеру и пульту, а на этапе 1 её негде проверить.

**Что нужно от учителя для превью-адреса** (по желанию, можно позже): в консоли Firebase → Project settings → Service accounts → Generate new private key; содержимое файла добавить в GitHub → Settings → Secrets and variables → Actions → `FIREBASE_SERVICE_ACCOUNT_KLAS_PULT`. После этого в CI добавляется публикация в превью-канал `preview` (только хостинг, правила и основной сайт не затрагиваются).

**Найдено сценариями и исправлено:**

- Поле «Додати учнів» очищалось только после ответа сервера и стирало имена, набранные за это время (а без связи кнопка оставалась заблокированной). Теперь поле очищается сразу, а при ошибке имена возвращаются.

**Что осталось на потом:** превью-адрес по-прежнему ждёт ключа сервисного аккаунта (см. этап 1).

- Кабинет: классы, ученики (список, вставка столбцом), карточки входа (SVG-картинки, печать), «Новий пароль», «Вийти з усіх пристроїв», сведения о входах.
- Ученик: код класса → имя → 4 картинки / пароль; гостевой вход (номер ПК + имя); номер ПК запоминается.
- Правила: `classes`, `joinCodes`, `roster`, `studentSecrets`, `bindings`, `isStudentOf()`.

**Готово, когда:**

- тесты правил: неверный пароль, чужой `uid`, смена пароля отключает старое устройство, ученик не читает `studentSecrets`;
- сценарий: учитель создаёт класс и учеников → ученик в другом браузерном контексте (Chromium 109, и отдельно мобильный размер экрана) входит по картинкам;

**Отступления и заметки:**

- **Вход в игру** — по баннеру после обычного входа ученика (картинки или слово), без отдельного PIN игры: ученики и так привязаны к классу, а результаты попадают в журнал по `studentId`. Гости урока в игре не участвуют.
